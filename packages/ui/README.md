# @workspace/ui

Shared UI primitives, generic layout components and the Tailwind CSS v4 theme for every app in this
workspace. The package ships raw TSX (no build step); the consuming app compiles it.

## What is inside

| Path                     | Contents                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------- |
| `src/components/*.tsx`   | shadcn/ui primitives (style `radix-nova`) and generic components built on them     |
| `src/lib/utils.ts`       | `cn` class-name helper                                                             |
| `src/styles/globals.css` | Tailwind entry point, theme tokens (light and `.dark`), `@source` for this package |
| `postcss.config.mjs`     | PostCSS config re-exported by apps                                                 |
| `components.json`        | shadcn CLI configuration for this package                                          |

Primitives: Alert, AlertDialog, Badge, Button, Card, Checkbox, Dialog, Input, Label, Select, Skeleton,
Table, Tabs, Textarea, Tooltip.

Generic components: AppShell, PageHeader, EmptyState, LoadingState, ErrorState, ConfirmDialog,
CopyButton. They receive all content through props and know nothing about a specific product.

## Usage

Import each component from its own subpath. There is intentionally no barrel file, because it would
mix server and client modules.

```tsx
import { Button } from "@workspace/ui/components/button";
import { cn } from "@workspace/ui/lib/utils";
```

Files that need the browser start with `"use client"`; everything else also works in React Server
Components. Wrap the tree in `TooltipProvider` once (the web app does this in its root layout).

## Adding a shadcn component

Run the CLI from the app workspace. It reads `apps/web/components.json` and writes the files into
this package:

```bash
cd apps/web
pnpm dlx shadcn@4.21.1 add <component>
```

Then, from the repository root:

```bash
pnpm install          # only if the CLI added a dependency; pin it to an exact version first
pnpm run format
pnpm --filter @workspace/ui run lint
pnpm --filter @workspace/ui run typecheck
```

## Where shared components go

- Reusable in more than one screen or app, no product wording, data only through props:
  `packages/ui/src/components/<name>.tsx`.
- Specific to one app or one page: keep it in that app (`apps/web/src/components/` or next to the
  page that uses it).
- There are no shared hooks yet, so the package has no `src/hooks/` directory and no `./hooks/*`
  export. When the shadcn CLI generates the first hook into `src/hooks/`, add
  `"./hooks/*": "./src/hooks/*.ts"` to `exports` in `package.json`.
