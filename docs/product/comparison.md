# Comparison with existing controls (RS-07)

Owner: researcher, document owner and presenter. Status: **first version, 3 October 2026.** Roadmap:
"Compare a small number of relevant authorization and agent-control products using primary
documentation. Record supported features, unavailable information, and overlap." Report 1.2: "Task
Passport should not be presented as inventing tool authorization, approvals, audit logging, semantic
guards, or information-flow control."

Every cell for an existing product is limited to **the page that was read** (sources in
[source-register.md](source-register.md)). "Not on the page read" means exactly that: the product may
offer it elsewhere. Task Passport's column is the **planned** design (report 1.2); nothing in it is
delivered until [claim-to-proof.md](claim-to-proof.md) marks it verified.

## Overlap and positioning

- **Tool authorization with identity and parameters is an existing capability** (S2). Task Passport
  must not present it as new. Its emphasis, per the report, is "a usable delegation boundary": scope
  issued per task, so the authority is "the records, destination, and limits of one authenticated job".
- **Content rails exist** (S3), and NVIDIA's own FAQ says no rail is a guarantee. Task Passport uses
  semantic checks the same way: they can only restrict, and deterministic scope and provenance stay
  the authority when a check misses.
- **Information-flow control exists in research** (S8) with a formal model and labels. Task Passport
  applies a much narrower version: two classifications and two server templates in one workflow. It
  "does not reproduce Fides or establish its formal guarantees".
- **What the report proposes as the distinguishing combination**, subject to delivery: an allowed
  read plus an allowed recipient still does not authorize exporting a report built from that read,
  and the task continues through an already-permitted template. None of the three pages read
  describes that combination; that is a statement about those pages, not a claim that nobody does it.
- No "first", "novel" or market claims; no statistics that we did not measure.

## OWASP Top 10 for LLM Applications 2025 (S13)

Criteria §1 asks teams to "review available sources (e.g. OWASP)". The mapping shows which planned
control answers which risk, and where the prototype does nothing. It is context, not a compliance
claim.

| OWASP 2025 risk                             | Planned control in Task Passport                                                                                                                                        | Coverage                                                                              |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| LLM01:2025 Prompt Injection                 | Semantic check and signatures on inputs and tool results; independent of them, deterministic scope and provenance deny the forbidden action (CL-10, CL-11, CL-14)       | Partial by design: specific attempted actions are constrained; no universal detection |
| LLM02:2025 Sensitive Information Disclosure | Field minimization, inherited report restrictions, vendor report from approved fields only, configured secret redaction (CL-05, CL-08, CL-13)                           | The two templates and configured patterns only; no universal tracking of paraphrases  |
| LLM03:2025 Supply Chain                     | Licenses recorded (RS-06); signature feed is trusted and validated; proposed sample rules for model-repository patterns (D-5)                                           | Minimal: the layer does not load models or verify model provenance                    |
| LLM04:2025 Data and Model Poisoning         | None                                                                                                                                                                    | Not addressed: no training or fine-tuning                                             |
| LLM05:2025 Improper Output Handling         | Model output is a typed proposal, validated before any effect; one action per step; the final result is a structured status; reports are rendered by the server (CL-08) | For the registered tools and templates                                                |
| LLM06:2025 Excessive Agency                 | Immutable passport, four registered tools, no shell or arbitrary HTTP, exact-action approval for the outbound effect (CL-03, CL-04, CL-09)                              | Core of the design                                                                    |
| LLM07:2025 System Prompt Leakage            | The semantic corpus has a direct request to reveal hidden rules (`direct_reveal_hidden_rules_v1`); credentials stay in Go, never in prompts                             | Partial; tested only as far as that corpus case                                       |
| LLM08:2025 Vector and Embedding Weaknesses  | None                                                                                                                                                                    | Not applicable: no embeddings or vector store in the MVP                              |
| LLM09:2025 Misinformation                   | The outbound vendor report is rendered from database fields, not model prose; the duplicate-reference finding "does not determine fraud or authorize payment"           | Only for the outbound report                                                          |
| LLM10:2025 Unbounded Consumption            | Shared and per-purpose call, token, time and concurrency limits reserved before dispatch; run expiry (CL-17, CL-18)                                                     | For the local model path                                                              |
