# Official requirements sheet (RS-03)

Owner: researcher, document owner and presenter. Status: **draft for the team to read at M0.** Written
on 3 October 2026 from:

- [S9] the competition rules, `competition-rules.pdf` ("Terms and conditions of the "AI CONTROL LAYER"
  Competition", 3 pages, 15 sections);
- [S10] the challenge criteria, `competition-criteria.pdf` ("AI Control Layer", 4 pages, 8 sections);
- [S11] the general HackYeah 2026 rules that [S9] is an annex to (see "General HackYeah rules" below);
- [S12] the HackYeah FAQ (answers F-4, F-5, F-8, F-13, F-14 below);
- the project report 1.2 (`task-passport-project-report.docx`) and the roadmap (`docs/roadmap/`) for
  where each requirement is covered.

This sheet separates what the organizers require from what the team chose. The roadmap coverage
column names sync points (X) and shared or researcher tasks (SH, RS), with the main side tasks (GO,
API, WEB) after a semicolon. **Nothing is built end to end yet**: coverage means "planned in", not
"delivered". The organizer questions are in [organizer-questions.md](organizer-questions.md).

The wording strength is the source's own: "must" is a mandate; "should", "think about" and "consider"
ask for a design answer, not a specific feature.

Criteria §1 (p. 1) is context, not a deliverable list. It names the risks the controls should answer:
access control and impersonation ("perform harmful and irreversible actions"), input validation and
prompt injection, output filtering of sensitive data, memory access and "runaway execution loops",
and asks for a layer that can "instantly inspect, redact, or block unsafe interactions in real-time".
It also says: "you should analyze the AI ecosystem deeply and review available sources (e.g. OWASP)"
(D-7).

## Proposed sample signatures for the feed (D-5)

For the Go implementer, who owns the feed (SH-46, GO-78). These are **proposals**: the field names
follow the report's description of a rule ("versioned rule data carrying issuer, revision, scope,
pattern type, response and integrity metadata") and the boundary names of the draft `config/policy.yaml`
(`model_input`, `tool_result`, `action_proposal`); the actual grammar is the open item
`feed grammar and trust`. Each pattern is a plain, case-insensitive substring after the same
normalization as `prompt_ignore_previous_v1`: no regular expression and nothing executable. The
strings are inert text; matching them executes nothing.

| Rule ID (proposed)                 | Attack class ([S10] §4.4)                         | Normalized pattern       | Boundaries                                      | Response | Why this pattern                                                                                                                                        |
| ---------------------------------- | ------------------------------------------------- | ------------------------ | ----------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `code_exec_python_os_import_v1`    | Malicious code execution                          | `__import__('os')`       | `model_input`, `tool_result`, `action_proposal` | block    | Injected text that asks an LLM application to evaluate Python commonly reaches the shell through this import. Nothing in the invoice workflow needs it. |
| `unsafe_deserialization_pickle_v1` | Unsafe deserialization                            | `pickle.loads(`          | `model_input`, `tool_result`, `action_proposal` | block    | Python pickle loading executes code embedded in the data; malicious pickled model files are the documented deserialization risk for model repositories. |
| `model_repo_trust_remote_code_v1`  | Supply-chain exploit targeting model repositories | `trust_remote_code=true` | `model_input`, `tool_result`, `action_proposal` | block    | The option that lets a model-hub loader run code shipped in a repository; text steering an agent or tool towards it is a supply-chain request.          |

Honest scope, for the claim-to-proof list: these rules match text at the layer's inspected boundaries.
Task Passport does not download models, load model files or deserialize data, so the rules show that
the managed feed can carry rules for these classes and that a judge can add or disable them; they do
**not** protect model-loading infrastructure. The reasoning in the last column must be backed by a
primary source in the source register (RS-06) before a slide repeats it. Each rule needs a positive
fixture (SH-49 owns `fixtures/`) and a suite case (X-100). Legitimate text that quotes these strings
would be blocked; in this workflow that false positive is acceptable and is recorded as one.
